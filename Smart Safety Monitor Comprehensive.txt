Smart Safety Monitor: Comprehensive Project Summary & Architecture
The Smart Safety Monitor is an AI-powered IoT safety compliance system designed to automatically detect whether industrial workers are wearing required Personal Protective Equipment (PPE) (such as safety helmets, protective gloves, work boots, and safety goggles) in real time.

🎯 Primary Purpose & Why This Project Was Created
In industrial environments, construction sites, and hazardous manufacturing facilities, ensuring that workers wear proper PPE is critical to preventing accidents and injuries. Manual monitoring by human supervisors is non-continuous, labor-intensive, and prone to oversight.

This project solves that problem by combining Computer Vision and Embedded Hardware:

Real-Time Video Surveillance: Monitors live camera feeds (PC webcam or IP camera).
AI Object Detection: Uses a fine-tuned YOLO11 computer vision model to recognize compliance vs. non-compliance (e.g., detecting no_helmet, no_gloves, no_boots, no_goggle).
Physical IoT Alerting: Immediately triggers a physical alarm unit (ESP32 microcontroller with Buzzer + LED) via USB serial whenever a safety violation is detected on camera.
🏗️ End-to-End System Architecture
┌─────────────────┐       ┌────────────────────────┐       ┌──────────────────────┐       ┌──────────────────┐
│   Webcam / IP   │ ────► │  Python + YOLO Model   │ ────► │  USB Serial Comm     │ ────► │  ESP32 Alarm     │
│   Camera Feed   │       │  (live_detect_esp32)   │       │  ("ALERT\n" signal)  │       │  (Buzzer + LED)  │
└─────────────────┘       └────────────────────────┘       └──────────────────────┘       └──────────────────┘
Input: Camera streams live frames to the Python host application.
Inference: YOLO inspects every frame for safety equipment violations above a confidence threshold ($0.5$).
Trigger: If a violation is identified, the Python script sends an ASCII string ALERT\n across the USB serial port to the ESP32 (filtered by a 5-second cooldown timer to prevent alarm spam).
Action: The ESP32 receives the trigger and drives GPIO pins high, sounding the buzzer and flashing the LED for 3 seconds to warn workers on-site.

🧠 1. Machine Learning & Model Training


model_train.ipynb

Why Created: This Jupyter notebook (executed on Google Colab with GPU acceleration) contains the complete machine learning workflow to build the custom PPE detector.
What it does:
Downloads and extracts a annotated PPE object detection dataset.
Verifies label/image pairing and analyzes class distribution.
Loads pre-trained YOLO11 weights (yolo11n.pt) and fine-tunes the network to recognize PPE items and violations.
Evaluates model metrics (mAP, Precision, Recall) and exports trained weights to PyTorch (.pt) and ONNX (.onnx) formats.

💻 2. Computer Vision & Python Runtime Scripts


live_detect.py

Why Created: Provides a software-only, standalone demonstration mode without requiring physical ESP32 hardware connected.
What it does:
Initializes OpenCV camera stream (CAMERA_INDEX = 0).
Runs YOLO prediction on each video frame using 

best.pt
.
Annotates frames with bounding boxes and labels in a window until q is pressed.


live_detect_esp32.py

Why Created: The main production script connecting AI detection with physical IoT alert hardware.
What it does:
Establishes a USB serial link with the ESP32 (COM5, 115200 baud).
Performs live YOLO detection and checks bounding boxes against violation sets (VIOLATION_CLASSES = {"no_helmet", "no_gloves", "no_boots", "no_goggle"}).
Implements an ALERT_COOLDOWN_SEC = 5 cooldown mechanism so the alarm isn't repeatedly triggered on every single frame.
Overlays real-time status banners (VIOLATION! in red or PPE OK in green) on screen.
🔌 3. Embedded Hardware & Firmware (ESP32)


esp32_ppe_alert.ino

Why Created: Firmware code to program the ESP32 microcontroller board using the Arduino IDE.
What it does:
Configures GPIO pin 4 (Buzzer) and GPIO pin 2 (LED) as outputs.
Listens over USB Serial (115200 baud) for ALERT string commands.
When ALERT is received, turns GPIO 4 and GPIO 2 HIGH for 3000 ms (3 seconds) to sound an audible alarm and illuminate an alert light, then resets to LOW.


esp32_connection_diagram.png

Why Created: Schematic/wiring guide for hardware assembly.
What it shows: Visual wiring layout linking ESP32 pins to the piezo buzzer, current-limiting resistor ($220,\Omega$), and LED.

⭐ Key Highlights & Smart Engineering Decisions
Hardware-Software Decoupling: Having both live_detect.py and live_detect_esp32.py allows testing the AI model on a PC without needing the ESP32 connected.
Cooldown Protection (ALERT_COOLDOWN_SEC): Prevents hardware chatter/flooding by guaranteeing a 5-second pause between consecutive serial alert triggers.

Page 1 – Problems Faced
Problems in Existing Construction Sites
Construction sites are among the most hazardous workplaces. Many accidents occur because workers do not follow safety rules or dangerous situations are not identified in time. Some of the major problems are:
1. PPE Non-Compliance
Many workers do not wear helmets, safety vests, gloves, or safety shoes properly, increasing the risk of serious injuries.
2. Manual Safety Monitoring
Safety officers must continuously observe workers, which is time-consuming and prone to human error.
3. Delayed Accident Detection
Falls, unsafe activities, or dangerous situations are often detected only after an accident has occurred.
4. Hazardous Environment
Construction sites may contain dangerous gases such as carbon monoxide (CO) or methane (CH₄), which are difficult to detect without sensors.
5. Lack of Real-Time Alerts
Many existing systems only record incidents and do not provide immediate warnings to workers.
6. High Cost of Advanced Safety Systems
Industrial safety monitoring systems using multiple cameras and edge AI devices are expensive for small and medium construction companies.
